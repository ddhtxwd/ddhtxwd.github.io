图形化编程Scratch

v0.1 · 应用目录 /scratch

图形化编程 Scratch 目前为beta版，仅供体验，可以使用的block还不够多是设备端的积木程序容器：在网页里用积木拼好程序，一键上传即写入设备 /scratch/scratch.py 并立即运行；应用管理器会把它识别为「积木程序」，可设为默认应用，开机直接进入你的程序。

注意：目前block还不够多，无法完成复杂功能，请等待后续版本，需要断开应用管理器的端口使用

运行逻辑总览

网页积木
 └─ 生成 MicroPython 源码
     └─ Web Serial（raw REPL）
         ├─ 创建 /scratch 目录（已存在则跳过）
         ├─ 缺少 app.json 时自动写入应用信息
         ├─ 以 base64 分块写入 /scratch/scratch.py
         └─ exec 运行 scratch.py，立即生效
  • 上传不会改动根目录的 main.py（设备启动脚本），程序以独立文件的形式放在 scratch/ 里，可反复覆盖上传。
  • 运行入口有两种：网页上传后在 REPL 中直接执行；或由应用管理器（开机默认应用或列表中选中）启动。

上传与运行过程

  1. 网页用 Blockly 把积木翻译成完整源码，右侧代码区可随时查看、复制或下载。
  2. 点击「上传并运行」后，网页通过 Web Serial 进入设备的 raw REPL。
  3. 确保 /scratch 目录存在；目录里没有 app.json 时自动生成一份，应用名固定为「积木程序」。
  4. 源码以 base64 分块写入 /scratch/scratch.py，写完立即在 REPL 中执行该文件。
  5. 启动阶段约 1.5 秒的串口输出（print、驱动提示等）会显示在网页的「串口日志」中；点击「停止」会发送中断信号结束程序。

网页需通过 http://localhost 访问，并使用支持 Web Serial 的 Chrome / Edge 桌面版。

从应用管理器启动

  1. 管理器扫描到 /scratch/app.json，按 entry → main.py → <app_dir>.py 的顺序找到入口脚本（本应用为 scratch.py）。
  2. 读取入口源码，在独立命名空间中执行：__name__ 为 __main__，__file__ 为入口路径。
  3. 执行期间工作目录切换到 /scratch，该目录会临时加入 sys.path；管理器初始化屏幕后 /driver 也在搜索路径中，可直接 import epd4in2b。
  4. 程序结束或抛出异常后，恢复工作目录与 sys.path，回收内存，重新扫描应用并回到管理器；异常会显示「启动失败」提示页。

生成的程序结构

积木生成的源码固定分为四段，硬件初始化只会在文件加载时执行一次：

# -------------------- 功能函数 --------------------
def _wait_key():
    ...

# -------------------- 硬件初始化 --------------------
epd = manage.get_epd()              # 复用管理器的屏幕对象
k_up = Pin(40, Pin.IN, Pin.PULL_UP)
...

# -------------------- 主程序 --------------------
while True:
    epd.fb_b.fill(0)
    epd.write_text(20, 20, '你好', color=0, font_size=3)
    epd.show()
  • 功能函数：按键等待、舵机、灯带等需要复用的辅助函数，按需生成。
  • 硬件初始化：屏幕、按键、引脚、PWM 等对象在这里创建，避免在循环里反复初始化。
  • 主程序：积木拼出的执行顺序，while True 表示一直运行。

屏幕与按键

屏幕为 400×300 三色墨水屏，黑色和红色各有一块画布（epd.fb_b / epd.fb_r）。绘制流程是：清空画布 → 写文字或图形 → 刷新显示。

  • 屏幕对象统一通过 manage.get_epd() 获取：SPI 初始化与中文字库（driver/GB2312-12.fon）路径都已处理好，不要自己再创建 EPD()。
  • 三色屏只支持全刷，「刷新显示」一次约 2~4 秒，期间屏幕闪烁属于正常现象。
  • 按键固定接线：上 GPIO40、下 GPIO39、确定 GPIO0，均为低电平触发（内部上拉）。
  • 「等待按键按下」会等按下、消抖、松手后返回 up / down / ok，适合做翻页与菜单。

应用配置 app.json

上传时自动生成的配置如下，已存在时不会覆盖，可以手动修改：

{"app_name":"积木程序","app_version":"1.0","app_dir":"scratch","entry":"scratch.py"}
字段说明
app_name管理器列表里的显示名称
app_version版本号，显示在名称右侧
app_dir写入 device.json 默认应用的标识
entry入口脚本名，确保管理器启动的是 scratch.py

删除 app.json 后应用会从管理器列表中消失，重新上传一次即可恢复。

退出与返回

  • 程序自然结束，或用「如果」加「break」跳出 while True 循环，就会回到应用管理器。
  • 长期运行的程序需要自己留退出条件（例如某次按键后结束），否则只能重新上电或点网页「停止」。
  • 从管理器启动时被中断会按异常处理，管理器捕获后同样回到列表。

常见问题

上传成功但屏幕没有变化？

先看「串口日志」是否报错；程序可能停在「等待按键按下」，或正在整屏刷新（2~4 秒）。确认设备上保留了 manage 与 driver 目录。

中文显示空白或乱码？

中文字库位于 driver/GB2312-12.fon，不能删除；屏幕对象要通过 manage.get_epd() 获取，才会加载字库。

按键没有反应？

按键固定接 GPIO40 / GPIO39 / GPIO0，低电平触发。若引脚被其它积木占用，或接线不同，需自行调整。

开机后没有进入积木程序？

在管理器中选中「积木程序」按「确定」将其设为默认应用；开机时按住上/下键会跳过默认应用，属于正常现象。

可以改应用名吗？

可以，直接编辑 /scratch/app.json 的 app_name；已经存在的配置在上传时不会被覆盖。
