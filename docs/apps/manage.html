应用管理器

v0.2 · 应用目录 /manage

应用管理器是设备的启动入口：开机后先按 device.json 的配置启动默认应用，应用退出或启动失败时回到管理器；也可以在开机时按住上/下键，跳过默认应用直接进入管理器。管理器把根目录下所有带 app.json 的应用列在 400×300 三色墨水屏上，并可将选中的应用设为默认应用。

功能简介

  • 扫描根目录中所有包含 app.json 的文件夹，按显示名称排序，管理器自身固定排在第一行。
  • 每页显示 7 个应用，顶部红色标题栏显示页码，底部显示应用总数与按键提示。
  • 默认应用右侧标有红色「默认」，选中行用红色描边框标识，文字均为黑色。
  • 按「确定」把选中的应用写回 device.json 并立即启动，下次开机自动运行它。
  • 开机时按住 GPIO39 或 GPIO40，可强制进入管理器，不启动默认应用。

开机启动流程

根目录 main.py 只调用 manage.boot()，由它决定这次开机运行什么：

上电
 └─ main.py → manage.boot()
     ├─ 按住 GPIO39 / GPIO40？── 是 ──→ 应用管理器
     └─ 否
         ├─ 读取 device.json 的「默认应用」
         ├─ 未配置 / 应用不存在 / 没有入口脚本 / 默认就是管理器 ──→ 应用管理器
         └─ 启动默认应用
             └─ 应用结束或抛异常 ──→ 应用管理器（选中默认应用所在行）
  • 开机检测在上电后约 200 ms 的窗口内进行，连续 3 次读到低电平即判定为按住。
  • 默认应用抛出的异常会被捕获并打印到串口，随后照常进入管理器，不会卡死。
  • GPIO0 是 BOOT 键，复位瞬间被拉低会进入下载模式，因此开机强制键使用 GPIO39/GPIO40。

三个按键均为低电平触发（内部上拉），在松开时生效；开机时已经按住的键会被忽略一次，避免进入管理器后误触发。

选择与默认应用

默认应用记录在根目录 device.json 中，值为应用的 app_dir（也兼容文件夹名或显示名称）：

{"默认应用":"manage"}
  • 按「确定」时，管理器先把选中的应用写回 device.json（保留其它字段），再启动它；选中「应用管理器」自身时只更新配置并重绘。
  • 没有入口脚本的应用（例如 driver 驱动库）不会写入配置，界面提示「无法启动」。
  • 写入失败时提示「设置默认失败」且不启动应用，方便及时发现文件系统问题。

应用目录约定

在根目录新建文件夹，放入 app.json 和入口脚本即可被识别：

/
├─ manage/          应用管理器
├─ scratch/
│   ├─ app.json
│   └─ main.py
└─ device.json      默认应用配置
字段必填说明
app_name否列表显示名称，缺省用文件夹名
app_version否版本号，缺省留空
app_dir否应用目录名，缺省用文件夹名；也是写入 device.json 的标识
entry否入口脚本名，缺省依次查找 main.py、<app_dir>.py

入口脚本优先级为 entry → main.py → <app_dir>.py，找到第一个存在的文件即运行。

{"app_name":"图形化编程","app_version":"0.1","app_dir":"scratch"}

应用启动与返回

  1. 读取入口脚本源码，在独立命名空间中执行，__name__ 为 __main__，__file__ 为入口路径。
  2. 执行期间工作目录切换到应用目录，应用内的相对路径以自身目录为准，该目录同时加入 sys.path。
  3. driver/ 已在 sys.path 中，应用可以直接 import epd4in2b。
  4. 入口脚本结束或抛出异常后，恢复工作目录与 sys.path，回收内存，重新扫描应用并回到管理器；异常会显示「启动失败」提示页。

应用要回到管理器，让入口脚本自然结束或 return 即可；长期运行的应用需要自己提供退出入口。

刷新与串口接口

三色墨水屏不支持局部刷新，翻页、启动返回、设置默认都会触发一次整屏重绘，约需 2~4 秒，期间屏幕闪烁属于正常现象。驱动的字库位于 driver/，管理器会自动处理加载路径。

按键不可用或没有接按键时，可在串口 REPL 中直接调用：

  • manage.list_apps()：打印扫描结果
  • manage.next() / manage.prev()：切换选中
  • manage.ok()：设为默认并启动
  • manage.show()：按当前状态重绘
  • manage.refresh()：重新扫描并重绘
  • manage.main()：进入管理器主循环

常见问题

开机没有启动默认应用？

依次检查 device.json 是否存在、字段名是否为「默认应用」、应用文件夹是否还在、入口脚本是否存在；串口会输出 [manage] 开头的判定日志。按住上/下键开机会主动跳过默认应用，属于正常现象。

为什么设置默认应用也要等几秒？

按「确定」后需要写文件、启动应用并整屏刷新，三色屏只能全刷，耗时主要来自屏幕。

应用启动失败怎么办？

屏幕会显示「启动失败」和异常摘要，完整堆栈在串口。修复后让应用正常结束或重新上电即可。

新增应用后列表没有变化？

应用必须位于根目录的文件夹内并带有 app.json。应用退出返回、在串口执行 manage.refresh() 或重新上电都会重新扫描。

驱动文件夹为什么不能设为默认？

driver 没有入口脚本，管理器会拒绝把它写入默认应用，避免开机无法启动。
